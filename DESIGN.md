# DESIGN.md — FLEXX

Дизайн-система интернет-магазина брендовых кроссовок. Обязательный ориентир перед созданием
компонентов и изменением интерфейса; применяется вместе с [AGENTS.md](./AGENTS.md).

## 1. Направление и границы

Современный минималистичный sneaker / streetwear e-commerce в премиальной чёрно-белой эстетике.
Товар — главный визуальный акцент. Ощущение качества создают фотография, типографика, свободное
пространство и точные выравнивания, а не декоративные эффекты.

Главный сценарий: найти пару → изучить товар → добавить в корзину → оформить заказ без регистрации.
Красота не должна скрывать цену, доступность, условия или основное действие.

Этот документ задаёт **целевой дизайн**, а не утверждает, что он уже реализован. Создание документа
не меняет стили, данные, маршруты и бизнес-правила приложения. Новые функции вводятся отдельными
задачами после появления необходимых данных и серверной логики.

### Основа референса

Визуальный источник: переданное изображение `UI_UX Design for a branded shoes market.jfif`.
Референс используется как композиционный ориентир; текст и предложения на нём не являются
инструкциями или подтверждёнными условиями магазина.

| Берём из изображения                         | Адаптация для FLEXX                                                  |
| -------------------------------------------- | -------------------------------------------------------------------- |
| Крупный кроссовок справа, заголовок слева    | На телефоне текст и фото идут последовательно; CTA остаётся заметным |
| Белый фон и светло-серые подложки фотографий | Семантические `background`, `muted`, `foreground`                    |
| Контрастные чёрные промоблоки и футер        | Редкие инверсные секции, а не тёмная тема всей витрины               |
| Ритм: hero → бренды → категории → товары     | Только секции с реальными данными и рабочими переходами              |
| Компактные карточки, много воздуха           | Более крупный текст и сенсорные области для телефона                 |
| Монохромные логотипы производителей          | Только корректные разрешённые материалы брендов                      |

Не переносим название SOLEX, золотые акценты, звёздочки рейтингов, сердечки, личный кабинет,
подписку, автоматический слайдер и рекламные обещания без соответствующей функциональности.
Название магазина остаётся FLEXX. Оригинальные названия производителей и моделей сохраняются.

### Принципы

- Один главный CTA в каждом блоке принятия решения; вторичные действия визуально спокойнее.
- Светлая витрина, тёмный текст, реальные цветные фотографии обуви. Не обесцвечивать сам товар.
- Чёткая сетка, умеренное скругление, минимум рамок. Не оборачивать каждый текстовый блок в Card.
- Каталог и покупка важнее промоконтента. На внутренних страницах нет большого рекламного hero.
- Никаких градиентов интерфейса, стеклянных панелей, неона, объёмных кнопок и декоративных теней.
- Полезная функция доступна без hover, анимации и обязательной регистрации.

## 2. Цвет и поверхности

Единственное место определения цветов — [src/app/globals.css](./src/app/globals.css).
В компонентах использовать семантические классы, не копировать числовые значения.
Ниже зафиксированы значения светлой палитры после внедрения общих UI-примитивов.

| Токен                                                 | Значение OKLCH       | Назначение                                     |
| ----------------------------------------------------- | -------------------- | ---------------------------------------------- |
| `background`, `card`, `popover`                       | `1 0 0`              | Основная белая поверхность                     |
| `foreground`, `card-foreground`, `popover-foreground` | `0.145 0 0`          | Заголовки и основной текст                     |
| `primary`                                             | `0.205 0 0`          | Главная кнопка, инверсная секция               |
| `primary-foreground`                                  | `0.985 0 0`          | Текст на primary                               |
| `muted`, `secondary`, `accent`                        | `0.97 0 0`           | Подложки фото, вторичные поверхности, hover    |
| `muted-foreground`                                    | `0.52 0 0`           | Вторичные подписи на проверенном фоне          |
| `secondary-foreground`, `accent-foreground`           | `0.205 0 0`          | Текст вторичных элементов                      |
| `border`                                              | `0.922 0 0`          | Декоративные разделители и рамки поверхностей  |
| `destructive`                                         | `0.577 0.245 27.325` | Ошибки и опасные действия, не рекламный акцент |

Внедрено: `ring` и `input` в светлой палитре — `oklch(0.439 0 0)`.
Общий `ui-focus` показывает сплошной контур 2 px с отступом 2 px для native и React Aria
focus-visible. Декоративный `border` остаётся светлым. Вторичный текст затемнён с 0.556 до 0.52:
это обеспечивает контраст больше 4.5:1 и на белой поверхности, и на `muted`.

Инверсный блок использует `bg-primary text-primary-foreground`; вторичный текст в нём тоже должен
сохранять читаемый контраст. Не применять `.dark` к рекламному блоку. Светлая кнопка внутри него
использует существующий `Button variant="inverse"` с контрастным светлым фокусом.

Статусы успеха и ожидания — нейтральная подложка, иконка и понятный текст. Цвет не единственный
носитель смысла. Красный допустим для ошибок; скидки оформляются монохромно. Золотой из референса
не входит в палитру. Цветные фотографии и оригинальные материалы брендов не являются UI-токенами.

Тёмная тема не входит в текущий объём. Существующие `.dark` переменные не означают её готовность;
`sidebar-primary` теперь связан с монохромным `primary`. Полную тёмную тему проверять отдельно.

## 3. Типографика

Базовая гарнитура — существующая `ui-sans-serif, system-ui, sans-serif` для `font-sans` и
`font-heading`. Это нейтральная основа с поддержкой кириллицы. Не подключать новый шрифт ради
отдельного экрана. При будущей смене гарнитуры проверять кириллицу, цифры и все начертания вместе.

| Роль                        | Телефон: размер / интерлиньяж | От 1024 px | Вес     |
| --------------------------- | ----------------------------- | ---------- | ------- |
| Hero                        | 36 / 40 px                    | 64 / 68 px | 700     |
| H1 внутренней страницы      | 28 / 34 px                    | 40 / 44 px | 600     |
| H2 секции                   | 24 / 30 px                    | 32 / 38 px | 600     |
| H3 / заголовок блока        | 18 / 24 px                    | 20 / 28 px | 600     |
| Название товара в сетке     | 14 / 20 px                    | 16 / 24 px | 500     |
| Основной текст, ввод        | 16 / 24 px                    | 16 / 24 px | 400     |
| Кнопка, label, цена в сетке | 14 / 20 px                    | 14 / 20 px | 500–600 |
| Подпись / метаданные        | 12 / 16 px                    | 12 / 16 px | 400–500 |
| Цена на странице товара     | 24 / 30 px                    | 28 / 34 px | 600     |

Размеры реализуются в rem; px в таблице рассчитаны для базы 16 px. Между мобильным и широким
hero допустим промежуточный размер 48 / 52 px. Заголовкам — `tracking-tight`, обычному тексту —
нормальный трекинг. Uppercase только для короткой надписи над заголовком, с межбуквенным интервалом
0.08em; не для абзацев, названий товаров и всех кнопок подряд.

Один H1 на страницу, последовательные H2/H3. Hero — предпочтительно 2–3 короткие строки без
принудительных desktop-переносов на телефоне. Текстовые описания ограничивать примерно 65ch.
Цены форматировать через существующий `formatPrice`, не терять копейки; для сравнения сумм —
`tabular-nums`. Длинное название в карточке переносится; не скрывать различающую часть модели
необратимым обрезанием. На странице товара название показывается полностью.

## 4. Сетка, ритм и форма

Основной шаг отступов — 4 px. Рабочая шкала: 4, 8, 12, 16, 24, 32, 48, 64, 80 px.
Отступы задаются Tailwind-классами в JSX; не создавать новый Container только ради обёртки.

| Параметр               | До 640 px     | 640–1023 px   | От 1024 px    |
| ---------------------- | ------------- | ------------- | ------------- |
| Поля страницы          | 16 px         | 24 px         | 32 px         |
| Между секциями         | 48 px         | 64 px         | 80 px         |
| Заголовок → содержимое | 16 px         | 24 px         | 24 px         |
| Зазор сетки товаров    | 12 px         | 16 px         | 24 px         |
| Колонки каталога       | 2             | 3             | 4             |
| Высота шапки           | минимум 64 px | минимум 64 px | минимум 80 px |

Общая максимальная ширина контента — 1280 px, по центру; футер и промополоса могут иметь фон
на всю ширину. Использовать стандартные пороги проекта: sm 640, md 768, lg 1024, xl 1280,
2xl 1536 px. Не добавлять брейкпоинты для единичного устройства.

При ширине меньше 360 px или увеличенном тексте сетку допустимо перевести в одну колонку,
если иначе не помещаются название, цена и действия. Не уменьшать шрифт ради двух колонок.
В каталоге с боковыми фильтрами от 1024 px допускаются три товарные колонки; четыре — только
если каждая остаётся не уже 200 px. На широком мониторе не растягивать карточки бесконечно.

Сохраняется существующий `--radius: 0.625rem`: sm 6 px, md 8 px, lg 10 px, xl 14 px.
Поля и компактные элементы — md; кнопки и фото — lg; hero и диалог — xl.
Полное скругление — только счётчики и небольшие метки. Товарные карточки без тени; отделяются
подложкой фото и отступами. Лёгкая тень допустима для перекрывающего контент диалога или меню,
но не как постоянный декор сетки.

## 5. Фотографии и графика

- Каталог: единый квадрат 1:1, светлая подложка `muted`, `object-contain`, видна вся пара или
  весь силуэт. Внутреннее свободное поле примерно 8–12%; масштаб сопоставим между карточками.
- Страница товара: квадратное основное фото; дополнительные ракурсы только при наличии данных.
  Не растягивать изображение и не подменять недостающие ракурсы дублями.
- Hero: крупный выразительный силуэт на нейтральном фоне. На desktop композиция около 45% текст /
  55% изображение; на телефоне отдельная область фото после текста. Значимые части обуви не обрезать.
- Lifestyle-фото допустимы в редакционных подборках. Товарное фото должно точно передавать цвет,
  материалы и особенности модели; не применять к нему декоративные фильтры.
- Текст и CTA — HTML поверх композиции или рядом, не часть растрового баннера. Под текстом
  должна быть спокойная контрастная область, без зависимости от конкретного кадрирования.
- Размеры области фото резервируются до загрузки. Для отсутствующего фото — нейтральная
  заглушка «Фото пока нет», без случайной обуви или выдуманного бренда.
- Alt описывает модель и ракурс; декоративные изображения имеют пустой alt. Логотип-ссылка
  получает доступное имя производителя. Не перерисовывать логотипы текстовым шрифтом.

Иконки — только `lucide-react`: 20 px в обычном действии, 24 px в навигации, 16 px рядом с
компактной подписью, единая толщина 1.5–2. Иконка не заменяет непонятное пользователю название.

## 6. Компоненты и состояния

Сначала проверять [src/shared/ui](./src/shared/ui), компоненты сущностей и `_components` раздела.
Основа интерактива — существующие React Aria обёртки; использовать их реальный API (`onPress`,
`isDisabled` и другие поддерживаемые props), не переносить `asChild` из другого UI-kit.

### Кнопки и ссылки

| Тип              | Вариант существующего Button | Использование                                |
| ---------------- | ---------------------------- | -------------------------------------------- |
| Основной         | `default`                    | В корзину, оформить заказ, применить фильтры |
| Вторичный        | `outline`                    | Альтернативный переход или действие          |
| Спокойный        | `secondary`                  | Локальное вспомогательное действие           |
| Без заливки      | `ghost`                      | Навигация, закрытие, вспомогательные иконки  |
| Текстовая ссылка | `link` / Next Link           | Информация и переходы в тексте               |
| Опасный          | `destructive`                | Удаление в панели, с понятной формулировкой  |

Целевая высота действий витрины — 48 px; минимальная сенсорная область любого действия —
44 × 44 px, включая иконки, удаление, пагинацию и счётчик количества. Главная кнопка на телефоне
занимает доступную ширину. Два CTA в узкой карточке размещать вертикально, а не сжимать подписи.

Размеры внедрены в общий Button: `default` и `lg` — минимум 48 px; `sm` и `xs` — минимум
44 px; `icon`, `icon-sm`, `icon-xs` — 44 × 44 px; `icon-lg` — 48 × 48 px.
Старые имена размеров сохранены для совместимости. Не уменьшать их локальными `h-*` / `size-*`.
`Input` — 48 px, `Textarea` — минимум 128 px, размер текста ввода — 16 px.

| Состояние     | Обязательное поведение                                                          |
| ------------- | ------------------------------------------------------------------------------- |
| Default       | Читаемая подпись, понятное главное действие                                     |
| Hover         | Небольшое изменение поверхности; без сдвига сетки                               |
| Pressed       | Краткое изменение тона; без скачка размеров                                     |
| Focus-visible | Сплошной контрастный контур 2 px с отступом 2 px; не обрезается контейнером     |
| Disabled      | Приглушённый вид, реальная блокировка действия, причина рядом при необходимости |
| Pending       | «Добавляем…» / «Оформляем…», сохранение ширины, запрет повторной отправки       |
| Success       | Краткое подтверждение и актуальное состояние корзины                            |
| Error         | Сообщение рядом с действием и доступный повтор                                  |

### Карточка товара

Порядок: изображение → название модели → категория или бренд при наличии → цена → доступность →
действие. Фото и название ведут на товар, кнопка корзины — самостоятельный элемент, без вложенных
кнопок в ссылку. Не делать весь Card кликабельным через обработчик на div.

Визуальная основа — спокойная карточка без внешней тяжёлой рамки; светлая рамка изображения
допустима. Не более двух коротких бейджей. «Нет в наличии» показывается явно, добавление отключено.
Не переопределять порог малого остатка в UI: бизнес-правило должно иметь одно место определения.
Нет данных о скидке, рейтинге или популярности — нет соответствующих меток.

### Поля и формы

Использовать `Field`, `FieldGroup`, `FieldLabel`, `Input`, `Textarea` и существующий вывод ошибок.
Подпись над полем, подсказка и ошибка под ним. Placeholder — пример, не замена label.
Ввод 16 px, высота однострочного поля минимум 48 px, расстояние между полями 24 px.
Обязательность объяснять текстом или единообразной легендой. Ошибка содержит способ исправления,
связана с полем через доступное описание; введённые значения сохраняются.

### Фильтры, диалоги и панели

На телефоне фильтры открываются через Sheet с названием, кнопкой закрытия и нижним действием
«Показать товары». На desktop — компактная строка или боковая колонка. Применённые фильтры
видны снаружи и сбрасываются; URL остаётся источником применённого состояния. Если есть кнопка
«Применить», локальный черновик коммитится в URL только по ней, закрытие отменяет черновик.

Dialog/Sheet имеют доступное название, удерживают фокус, закрываются предсказуемо и возвращают
фокус на исходную кнопку. Длинное содержимое прокручивается внутри; действия остаются доступны
при открытой экранной клавиатуре. Не строить собственную модальную систему.

### Загрузка, пустота и ошибки

- Skeleton повторяет геометрию будущей карточки; не показывает фиктивные цены и остатки.
- Пустой каталог: «Ничего не найдено», пояснение, «Сбросить фильтры».
- Пустая корзина: «В корзине пока пусто», «Перейти в каталог».
- Сбой загрузки: «Не удалось загрузить товары», действие повтора; не выдавать ошибку за пустоту.
- Уведомления — через существующий Sonner. Существенная ошибка остаётся также в форме.

## 7. Композиция страниц

### Главная

1. Необязательная узкая промополоса: одно подтверждённое условие, без бегущей строки.
2. Шапка: FLEXX, каталог, поиск, корзина со счётчиком; на телефоне — компактное меню.
3. Один hero: короткое позиционирование, фото, «В каталог»; вторичный CTA только при полезной цели.
4. Бренды — при появлении соответствующих данных и страниц/фильтра; затем категории из БД.
5. Товарная подборка: 4–8 реальных товаров, «Смотреть всё». Случайную выборку не называть бестселлерами.
6. Необязательный чёрный редакционный или акционный блок с подтверждённым предложением.
7. Короткая информация о покупке и условиях; футер с действующими ссылками.

Hero не обязан занимать весь первый экран. На телефоне CTA появляется до большого изображения.
Стартовая версия — статичная, без карусели и точек слайдера. Бренды не должны становиться
мелкой нечитаемой лентой. В футере на телефоне секции идут вертикально или в доступных Accordion.

### Каталог

H1 → поиск / категории / сортировка → активные параметры и число результатов → сетка → пагинация.
Каталог сохраняет поисковый запрос и параметры при навигации. Сортировки и фильтры отражают только
поддерживаемые правила `src/entities/product/catalog-params.ts`; новые фасеты не рисуются как
работающие до реализации. Без бесконечной прокрутки по умолчанию.

### Страница товара

Телефон: хлебные крошки → название → фото → цена и наличие → параметры покупки → CTA → описание
и условия. Desktop: фото занимает примерно 60%, информация 40%; блок покупки можно закрепить
в пределах секции, если он помещается по высоте. Дополнительные сведения — через Accordion.

**Размеры обуви — будущая функциональность.** В текущем Product есть общий stock и одно imageUrl,
но нет размерных вариантов, брендового справочника и галереи. Нельзя рисовать работающий выбор
размера поверх общего остатка. До отдельной реализации сохранять действующий сценарий товара.

После появления вариантов: явно указать систему размеров, показывать сетку кнопок минимум
44 × 44 px, выбранный размер выделять чёрной заливкой и доступным selected-состоянием,
недоступный — блокировкой и текстовым пояснением. Не выбирать размер автоматически. До выбора
действие объясняет «Выберите размер»; после — «В корзину». Таблица размеров использует данные
конкретного бренда. Выбранный вариант сохраняется в корзине и заказе с серверной проверкой остатка.

Мобильная закреплённая панель покупки допустима только при необходимости: цена и одно действие,
место под неё в контенте и учёт `env(safe-area-inset-bottom)`. Она не перекрывает сообщения,
последнее поле формы, футер или системную клавиатуру.

### Корзина и оформление

Строка: миниатюра, полное название, параметры при наличии, цена, количество, сумма, удаление.
На телефоне элементы переносятся в несколько строк; на desktop справа можно закрепить итог.
Изменение количества доступно кнопками с понятными именами, ограничения остатка объясняются.

Оформление без регистрации, одна колонка полей на телефоне. Показывать только необходимые
действующему процессу поля. Итог и доступные условия видны перед «Оформить заказ». Не добавлять
шаг оплаты, промокод, аккаунт или фиктивный расчёт доставки. Изменение цены/остатка объясняется
рядом с затронутым товаром. При сбое корзина и введённые данные сохраняются.

Страница подтверждения сообщает об успешном создании заказа, показывает предусмотренные
сценарием сведения и следующий шаг; не называет заказ оплаченным без подтверждённой оплаты.

### Административная панель

Та же типографика, цвета, поля и фокус, но более плотная утилитарная композиция. Никаких hero,
рекламных баннеров и крупных lifestyle-фото. Переиспользовать общую административную таблицу,
TanStack Table и существующие формы. Числа выравнивать вправо, статусы сопровождать текстом.
На телефоне таблица может прокручиваться внутри контейнера; сама страница — нет.
Критичные действия и редактирование доступны с клавиатуры и без hover.

## 8. Текст и достоверность

Язык интерфейса — русский; тон короткий, спокойный, уверенный. «В корзину», «Выбрать размер»,
«Продолжить покупки», «Оформить заказ». Не использовать технические сообщения и внутренние коды.

Не обещать «100% оригинал», бесплатную доставку, возврат за 30 дней, скидку или срок доставки
на основании изображения. Условия должны быть подтверждены магазином. Не придумывать отзывы,
дефицит, старую цену, таймеры и показатели продаж. Пустая секция скрывается, а не заполняется моками.
Логотип производителя не должен создавать неподтверждённое впечатление официального партнёрства.

## 9. Доступность и движение

Целевые критерии проверки: контраст обычного текста минимум 4.5:1, крупного — 3:1;
существенных границ элементов и индикатора фокуса — 3:1 к соседнему фону. Проверять итоговый цвет,
включая opacity: наличие семантического токена само по себе не гарантирует контраст.

Полная клавиатурная навигация, видимый фокус, доступные имена и семантические landmarks обязательны.
На увеличении 200% текст не обрезается; при ширине 320 CSS px интерфейс перестраивается.
Не отключать zoom. Учитывать длинные русские названия и ошибки. Результат операции и изменения
корзины сообщать вспомогательным технологиям без лишних повторных объявлений.

Переход цвета/границы — 120–180 ms; появление Sheet/Dialog — 180–240 ms, спокойное ease-out.
Не анимировать все свойства через `transition-all` без необходимости. Не поднимать карточки
на hover, не применять параллакс, бегущие строки и автоматическую смену промо. При
`prefers-reduced-motion` убирать пространственное движение и пульсацию skeleton; смысл сохраняется.
Для обычного UI достаточно CSS; `motion/react` — только для конкретной сложной потребности.

## 10. Внедрённая основа и дальнейшее развитие

Внедрены глобальные цвета, типографическая основа, контрастный фокус, reduced motion и стили
существующих компонентов в `src/shared/ui`. Их React Aria API и экспорты сохранены.

| Компонент                                | Правило переиспользования                                                                                                              |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Button / LinkButton                      | Существующие варианты плюс `inverse` для чёрной секции; размеры описаны выше                                                           |
| Card                                     | `variant="outline"` по умолчанию для формы/блока; `variant="plain"` без внешней рамки и внутренних боковых отступов для товарной сетки |
| Input / Textarea / InputGroup            | Единый контрастный контур, 16 px ввод; фокус группы отображается один раз вокруг неё                                                   |
| Toggle / ToggleGroup                     | Выбранное состояние чёрное с белым текстом, доступное состояние React Aria сохранено                                                   |
| Dialog / Sheet                           | Нейтральное затемнение без blur, читаемые заголовки, крупное закрытие и прокрутка длинного содержимого                                 |
| DropdownMenu / Pagination / Sidebar      | Действия минимум 44 px, заметные выбранные и клавиатурные состояния                                                                    |
| Table / Badge / Empty / Tooltip / Sonner | Общие поверхности, типографика и монохромные информационные состояния                                                                  |
| Skeleton                                 | Спокойная подложка с отключением пульсации при reduced motion                                                                          |

Товарная карточка использует plain Card, квадратное фото с object-contain и вертикальные действия.
Сетка: две колонки на телефоне, одна ниже 360 px, три от sm, четыре от lg; loading-состояния
повторяют эту геометрию. Изменение этих компонентов не добавляет размерные варианты или галерею.

Полная композиция главной, обновление контента и фотоматериалы остаются дальнейшими задачами.
Существующие страницы могут явно задавать размеры заголовков и отступы; при их обновлении
сверять эти переопределения с разделами 3–4, не считать их частью новой системы.
Данные брендов, размеров и дополнительных ракурсов вводятся только с серверной поддержкой.
Новые компоненты строить на этой основе, без параллельного stylesheet или UI-kit.

## 11. Готовность нового компонента

- Использует существующие примитивы, семантические токены и согласованные размеры.
- Имеет понятное назначение в покупке или управлении магазином; не добавлен только ради референса.
- Проверен на ширинах 320, 375, 768, 1024 и 1440 px; нет горизонтального скролла страницы.
- Выдерживает длинное название, отсутствующее фото, нулевой остаток и большую цену.
- Проверены loading, empty, error, disabled, pending и success там, где они применимы.
- Доступен клавиатурой и касанием, сохраняет видимый фокус, корректные label и порядок чтения.
- Контраст, увеличение текста и reduced motion проверены на реальном интерфейсе.
- CTA не перекрывает контент, данные и условия не выдуманы, покупка без регистрации сохранена.
- Для реализации выполнены проверки из AGENTS.md; для изменения этого документа достаточно
  форматирования и проверки ссылок.
