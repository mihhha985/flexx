# Работа с Prisma

В проекте используются Prisma CLI 8.0.0-rc.12 и `@prisma/orm-postgres` 8.0.0-rc.8. Версии RC фиксированы; обновляйте их с проверкой совместимости Composer.

Контракт `src/prisma/contract.prisma` описывает Category, Product, Order и OrderItem. После изменения выполните `npm run contract:emit` и сохраните сгенерированные `contract.json` и `contract.d.ts` вместе с исходным контрактом.

Клиент создаётся в `src/prisma/db.ts`. Его импортируют репозитории сущностей; сервисы работают через функции репозиториев. В прямом режиме используется `DATABASE_URL`, в Composer — сервисная привязка.

Команды:

- `npm run db:verify` — проверка соответствия БД контракту.
- `npm run migration:status` — состояние миграций.
- `npm run migration:plan` и `npm run migration:show` — подготовка и просмотр миграции.
- `npm run migrate` — применение миграций к выбранной базе.
- `npm run db:init` — инициализация новой базы.
- `npm run seed` — добавление отсутствующих демоданных без удаления существующих.

Генерация контракта не применяет изменения к БД. Сначала проверяйте миграцию на отдельной базе. Снимки схемы в репозитории сами по себе не доказывают возможность воспроизвести историю миграций с нуля.

`npm run db:reset` удаляет данные и предназначен только для осознанного сброса тестовой базы.
